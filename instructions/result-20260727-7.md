# Gemini CLI実環境接続と対話型URS 実装結果

## 実装概要

Gemini CLIの現物を確認し、旧設定の架空オプションを廃止して、長文を標準入力へ渡す専用アダプター、診断、dry-run、明示的な実環境スモークを実装した。同時に、既存の作品・SQLite状態・メール系列・次工程を流用する対話型URS工程を追加した。URSは一問ずつ回答・保留・修正・再開でき、安定したプレビューと非上書きの版付き確定Markdownを生成する。

## Gemini CLI確認結果と呼出し契約

ローカルの現物はGemini CLI `0.45.2`。`--help`で次を確認した。

- 非対話: `-p/--prompt`
- モデル: `-m/--model`
- 標準入力: promptへ追加される正式対応
- 出力: `-o/--output-format`の`text`、`json`、`stream-json`
- 終了状態: プロセス終了コード

実際の契約は次の形で、特定モデル名は設定から解決する。

```text
gemini [設定済み固定引数] --model <model> --output-format text --prompt <短い固定指示>
```

タスクMarkdown全文は`subprocess.run(..., input=...)`で標準入力へ渡す。stdoutが空でなく不正値を含まないことを確認し、Pythonが`result.md`へ原子的に保存する。Windowsでは`.cmd`、POSIXでは通常の実行ファイルを`shell=False`で解決する。旧設定の存在しない`--input`、`--output`は削除した。

エラーは、未導入、認証・利用資格、タイムアウト、非ゼロ終了、空出力、不正出力に分類する。例外や診断へタスク本文とstderr全文を複製せず、Gemini失敗時に別AIへフォールバックしない。

## 長文参照渡し

argvへ入るのは実行名、固定オプション、短いモデル名、出力形式、短い固定指示だけである。タスクMarkdown、URS、メール本文、小説本文は標準入力またはパス・ID参照を使う。10万1文字の入力テストで、argv合計長が1000文字未満のまま本文長に比例せず、本文断片を含まないことを確認した。dry-runはモデル、タイムアウト、引数、参照パスを本文なしで返す。

## URS質問・回答・状態モデル

`urs-maker`は本文を書かず、次の12領域を安定した質問IDで一問ずつ扱う。

1. 仮題・呼び名
2. 物語の主軸
3. ジャンルと舞台
4. 主人公の成長
5. 主要な関係性
6. 雰囲気、文体、読後感
7. テーマと回避事項
8. 想定読者
9. 長さ、構成、視点
10. 好きな作品の具体的要素
11. 主人公の成功範囲
12. 絶対条件

質問は意図、2〜4個の選択肢、各影響、推奨と理由、保留、自由記入を持つ。回答状態は`confirmed`、`provisional`、`deferred`、未回答、根拠は`user`、`known`、`ai_inference`、`source`を区別する。既知情報は仮決定として再質問を省略でき、AI推定をユーザー回答なしに確定へ昇格しない。

現在質問以外への通常回答、二重回答、未知ID、別作品混入を拒否する。明示修正は旧値・新値・状態・根拠・時刻を履歴へ追記する。

## SQLiteスキーマ変更

既存状態DBへ冪等に次を追加した。`mail/`のDBスキーマは変更していない。

- `urs_sessions`: セッション、作品、状態、質問定義版、次質問、URS状態、開始メール
- `urs_answers`: 質問ID・順・版、回答、回答状態、根拠、作成・更新時刻
- `urs_answer_history`: 回答修正の追記型監査記録
- `urs_documents`: セッション、作品内版、状態、成果物パス、作成時刻

作品ごとの進行中セッションを最大1件に制限し、再起動後は保存された未回答の次質問から再開する。

## CLI使用例

```powershell
py -3 -m kobo.cli --config kobo.json gemini-doctor
py -3 -m kobo.cli --config kobo.json gemini-smoke
py -3 -m kobo.cli --config kobo.json --dummy urs-start --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-question --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-answer work-name "仮題" --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-defer core-axis --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-answer work-name "改訂仮題" --work my-story --revise
py -3 -m kobo.cli --config kobo.json --dummy urs-answer-history work-name --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-status --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-preview --work my-story
py -3 -m kobo.cli --config kobo.json --dummy urs-finalize --work my-story
```

`urs-interactive`は同じAPIを人間向け端末対話で利用する。既知回答は本文argvを避け、`--known-json <path>`で取り込む。

## 中断再開、版管理、メール・次工程連携

回答ごとにSQLiteトランザクションで確定するため、異常終了後も回答を失わない。プレビューは`URS.preview.md`へ同じ構造で再生成し、確定版は作品単位で`URS.v001.md`以降の新しい版へ保存する。確定済み版を黙って上書きしない。

開始時は工房長から`urs-maker`へメールを登録する。確定時は同じ会話系列の子メールで`urs-maker`から`planner`へ確定URSのパスを通知し、作品の次工程を企画担当へ設定する。CLIスモークで、その後のダミー企画工程まで引き渡せることを確認した。
