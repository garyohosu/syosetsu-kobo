# 作業結果報告: AIエージェント間メールの待機ポーリング型ワーカー

## 実装概要

## DBスキーマ変更

スキーマバージョンを`PRAGMA user_version`で3へ更新した。既存テーブルへ`lease_token`と`lease_generation`を冪等に追加し、既存メール・既読情報は削除しない。新規DBは可能な環境で所有者のみのファイル権限を設定する。保存期間、アーカイブ時期、削除時期は`TBD-010`として未決である。

## 状態遷移

`pending` → `processing` → `completed`または`failed`。処理完了、既読、返信済みは別々に保持する。失敗時はエラー、試行回数、開始・完了・更新時刻を記録する。

## 排他制御方式

SQLiteの`BEGIN IMMEDIATE`トランザクション内で、時刻とメールIDの順に対象を選択し、`pending`から`processing`へ変更する。リーストークンと世代番号を完了・失敗更新の条件に含め、回復後の古い所有者による更新を拒否する。

## 再試行と回復方式

`max_attempts`は初回を含む合計試行回数で、既定値は3。旧名`max_retries`も互換エイリアスとして利用でき、同時指定の矛盾は拒否する。一定時間を超えた`processing`は回復処理で再び処理可能にする。CLI子プロセスはタイムアウト時に終了させるが、Pythonハンドラーは信頼済み内部処理として協調停止範囲に限定される。

## 無限往復防止方式

親メールから会話ID、親メールID、ホップ数を導出・検証し、親受信者・系列・ホップ値の不整合や循環を拒否する。最大ホップ数を超えた場合は処理を停止し、設定された管理エージェントへエスカレーションする。外部副作用の重複防止はハンドラー側で系列IDまたはメッセージIDを用いて冪等化する。

## CLI使用例

```powershell
py -3 mail/agent_mail.py --db mailbox.sqlite3 init
py -3 mail/agent_mail.py --db mailbox.sqlite3 worker-once --agent analyst --command py -c "print('handled')"
py -3 mail/agent_mail.py --db mailbox.sqlite3 worker-loop --agent analyst --interval 1 --max-attempts 3 --timeout 60 --command py -c "print('handled')"
py -3 mail/agent_mail.py --db mailbox.sqlite3 recover --stale-after 300
py -3 mail/agent_mail.py --db mailbox.sqlite3 worker-status --agent analyst
```

未登録の対象エージェントはCLIワーカー起動時に安全な既定値で登録され、既存の表示名は上書きしない。本文を無条件にコマンドとして実行せず、CLIコマンドは明示的に登録・指定する。
