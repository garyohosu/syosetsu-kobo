# Python製マルチAIエージェント基盤 実装結果

## 実装概要

Python標準ライブラリだけで、作品・アクティブ作品・工程・実行履歴・停止／再開・メール依頼・AI／CLI起動を管理するMVPオーケストレーターを実装した。役割は`agents/*.md`、コマンドとモデルは`kobo.json`へ分離し、本文作成工程はGeminiへ強制ルーティングする。`--dummy`では外部AIを起動せず、企画→Gemini本文担当→批評の3工程を完走する。

## エージェントMarkdown形式

人間向けMarkdown内に単一の`json`コードブロックを置く。`agent_id`、表示名、役割、アダプター、モデル、入力、出力、次工程、許可操作、禁止事項、タイムアウト、合計試行回数が必須である。JSONは標準`json`だけで厳密に読み、必須不足、型違反、重複ID、未定義次工程、不正IDを拒否する。`prose-writing`を持つ定義は`adapter=gemini`以外を拒否する。

## オーケストレーターと保存責務

SQLiteはアクティブ作品、現在／次工程、担当、状態、入力・出力・エラー・時刻、メール系列、コマンド記録を管理する。Markdownは人間向けタスクと成果物を保持し、一時ファイルから`os.replace`で原子的に確定する。既存成果物は変更せず、再試行ごとに新しい実行ディレクトリを作る。

作品IDは`^[a-z][a-z0-9-]{2,62}$`。実行IDは`run-YYYYMMDDThhmmss.ffffffZ-<12桁hex>`である。状態は作品が`pending/running/completed/failed`、実行がこれらに`interrupted`を加えた集合である。

## GeminiルーティングとAI／CLIアダプター契約

文章作成権限を持つ`writer`はGemini専任である。モデルは設定のエージェントID指定、アダプター指定、Markdown既定値の順に解決する。Geminiの登録がない、起動失敗、タイムアウト、出力不在は失敗として保存し、別AIへフォールバックしない。

CLIテンプレートへ展開できる値は`agent_path`、`task_path`、`mail_db`、`mail_id`、`run_id`、`run_dir`、`output_path`、`model`だけである。未知の変数と空コマンドを拒否し、`subprocess.run`は引数配列、`shell=False`、タイムアウト付きで実行する。

## 長文参照渡し

タスク本文・小説本文・メール本文はCLI引数へ渡さない。CLIへ実際に渡るダミー例は次のとおり。

```text
dummy --agent-definition <repo>/agents/writer.md --task <repo>/.kobo/works/story/runs/run-.../task.md --mail-db <repo>/.kobo/mail.db --mail-id 2 --run-id run-... --output <repo>/.kobo/.../result.md
```

10万1文字の入力を作るテストで、引数合計長が本文長に比例せず、本文断片が含まれないことを確認した。Windowsのコマンドライン長制限を回避する共通契約であり、Antigravity固有の例外処理ではない。

## 中断・再開とメール統合

安全停止は停止イベント設定後に新工程を取得しない。再起動時に残った`running`履歴を`interrupted`へ確定し、SQLiteの`next_agent`から再開する。完了済み工程は再実行しない。失敗再試行も新しい実行IDを使う。

各工程は既存`AgentMail`へ工房長から担当エージェント宛ての依頼を登録する。メールID、`work-<work-id>`会話ID、実行ID、タスクMarkdownパスを実行履歴へ対応付ける。メール本文をCLIへ転送しない。`mail/`のスキーマ、CLI、コピー利用を変更していないため後方互換性を維持した。

## 設定項目と優先順位

保存先、状態DB、メールDB、定義ディレクトリ、アダプター別コマンド、モデル、タイムアウト、最大試行回数、最大ホップ、エスカレーション先を設定可能にした。設定ファイルは`--config`、`KOBO_CONFIG`、既定`kobo.json`の順。パス環境変数はファイル値より優先し、相対パスは設定ファイル基準である。未知アダプター、不正値、存在しない定義、ルート外参照を拒否する。

## CLI使用例

```powershell
py -3 -m kobo.cli --config kobo.json --dummy work-create sample-story "サンプル"
py -3 -m kobo.cli --config kobo.json --dummy agents
py -3 -m kobo.cli --config kobo.json --dummy dry-run --work sample-story
py -3 -m kobo.cli --config kobo.json --dummy run-step --work sample-story
py -3 -m kobo.cli --config kobo.json --dummy continue --work sample-story
py -3 -m kobo.cli --config kobo.json history --work sample-story
py -3 -m kobo.cli --config kobo.json --dummy retry <run-id>
```

成功・失敗は`ok`を持つJSONで返し、失敗時は非ゼロ終了コードとなる。
